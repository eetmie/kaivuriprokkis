Hydraulic Actuator Workflow (Parquet)

1) Record data
- Run `python simple_drive.py` and use button A to start/stop a set.
- Each set writes `drive_log_*.parquet`; active IMU capture also writes `imu_raw_*.parquet`.
- Keep multiple 5-10 minute sets with reversals, coupled joints, varied poses, and cold/warm hydraulics.
- Continuity is defined by `timestamp`; there are no generated sample/stale columns.

2) Inspect simple baselines
```bash
python data_collection/benchmark_actuator_models.py \
  --input "data_collection/hydraulic_data/*.parquet"
```
The benchmark also accepts legacy CSV logs.

3) Train the Isaac actuator model
```bash
python train.py --data /path/to/hydraulic_data --out runs/my_run --device cuda
```
The loader resamples each continuous timestamped segment to 100 Hz and splits at gaps or non-finite required signals. Legacy `--csv` and CSV files remain supported.

4) Evaluate before using the model in simulation
```bash
python eval.py --model runs/my_run --data "held_out/*.parquet"
```
Use free-running trajectory position MAE as the checkpoint-selection metric. Also inspect final position error, velocity error, rest drift, and one-step loss/R2 as diagnostics.

Practical data-quality targets
- Minimize timestamp gaps and invalid joint velocities.
- Collect enough active command time in both directions.
- Include simultaneous two/three-joint motion and direction reversals.
- Keep whole held-out driving sessions for the final generalization report.
- Good one-step loss with poor rollout means the autoregressive model is not stable enough.
