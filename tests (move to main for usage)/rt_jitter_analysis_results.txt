===========================================================================
KEY FINDING: Python Garbage Collector causes ~55ms spikes
===========================================================================

The ~55ms max jitter spikes observed in all tests WITH garbage collection
enabled are caused by Python's GC, NOT the RT scheduler or I2C driver.

Disabling GC reduced max jitter from 55ms to ~4ms (13x improvement).

===========================================================================
RECOMMENDATIONS
===========================================================================

1. USE SCHED_FIFO PRIORITY 10
   - Provides all RT scheduling benefits
   - Not aggressive enough to starve system tasks
   - Higher priorities provide no measurable benefit

   Command: sudo chrt -f 10 python3 your_script.py

2. CONTROL GARBAGE COLLECTION - HYBRID APPROACH (RECOMMENDED)

   Disabling GC entirely is risky for long-running processes.
   Instead, use this hybrid approach that schedules GC during idle time:

   ```python
   import gc
   import time

   gc.disable()  # Disable automatic GC

   # Track last collection times
   last_gen1 = time.perf_counter()
   last_gen2 = time.perf_counter()

   def do_gc_if_headroom(headroom_ms):
       """Call this after work, before sleep, with available headroom."""
       global last_gen1, last_gen2
       now = time.perf_counter()

       if headroom_ms > 5:  # Only if we have 5ms+ headroom
           if now - last_gen2 > 30:      # Full GC every 30s
               gc.collect(2)
               last_gen2 = last_gen1 = now
           elif now - last_gen1 > 5:     # Gen1 every 5s
               gc.collect(1)
               last_gen1 = now
           else:                          # Gen0 when available
               gc.collect(0)
   ```

   Why this works:
   - Gen0 is fast (~0.1ms), runs frequently, handles short-lived objects
   - Gen1 every 5s catches medium-lived objects
   - Gen2 every 30s prevents long-term memory growth
   - Only runs when headroom available - no deadline interference

   Test results with hybrid approach (60 seconds @ 20Hz):
   - Max jitter: 4.8ms
   - P99: 50.7ms
   - Missed deadlines: 0
   - Memory stable (15.7MB)
   - GC ran: gen0 ~1189x, gen1 10x, gen2 1x

===========================================================================
ADDITIONAL OBSERVATIONS
===========================================================================

- The 200kHz I2C bus speed helps reduce communication overhead but the
  main bottleneck is MCP3424 conversion time (~4.17ms at 12-bit mode)

- Software bit-banged I2C (bus 3) adds some variability vs hardware I2C,
  but is acceptable for 20Hz operation

- The ~4ms max jitter with GC disabled appears to be from occasional
  I2C bus contention or kernel thread preemption - acceptable for
  soft real-time control

- Python's GC pause of ~55ms suggests significant object churn during
  ADC reading - could investigate object pooling to reduce allocations
